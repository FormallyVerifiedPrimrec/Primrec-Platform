PrimRec Platform

A full-stack web application for writing, verifying, and sharing primitive recursive functions. Users solve programming challenges, submit verified solutions, vote on community challenges, and compete on a ranked leaderboard.

Request Flow

1
Browser loads SPA
Nginx serves index.html. React Router handles client-side routing.
2
Supabase Auth
User logs in via Supabase. JWT stored in browser. AuthContext provides session state.
3
API calls
Frontend challengesApi.ts injects JWT via Authorization: Bearer. Nginx proxies /api/* to ChallengesBackend.
4
Backend processing
IEndpointFilter extracts token. ChallengesService resolves user ID via auth/v1/user, queries Supabase REST API.
5
Database interaction
PostgREST API with Row Level Security. Triggers recompute votes on challenges from user_interactions.

Frontend Architecture

Routing

React Router v7 with BrowserRouter. Auth-gated routes via ProtectedLayout wrapper. Unauthenticated users redirected to /login.

State Management

AuthContext for session. ThemeContext for 12-theme system with OLED toggle. useLocalStorageState for editor content persistence.

Editor

Monaco Editor with custom PrimRec language: Monarch tokenizer, semantic tokens, hover provider, context-aware autocompletion, diagnostic markers.

Theme System

6 hue families × dark/light = 12 themes. Colors generated from base hue. OLED black toggle for dark variants. Persisted in localStorage.

Backend Architecture

API Style

ASP.NET Core 8 Minimal APIs. Endpoints mapped via MapGroup("/api"). CORS enabled. Swagger in dev mode.

Auth Pipeline

Custom IEndpointFilter extracts Bearer token. Service layer resolves user ID via Supabase auth endpoint. RLS enforced at DB level.

Data Access

SupabaseHttpClient wraps PostgREST API. Constructs REST URLs, handles JSON serialization, maps rows to DTOs.

Error Handling

Global middleware catches UnauthorizedAccessException → 401, ArgumentException/InvalidOperationException → 400, SupabaseRequestException → 502.

Database Schema

erDiagram challenges { uuid id PK uuid creator_id FK string title string description string template_func string postcondition string suggested_solution int votes "computed by trigger" timestamp created_at } user_interactions { uuid user_id PK "part of composite PK" uuid challenge_id PK "part of composite PK" int vote_type "-1, 0, or 1" bool has_solved string best_submission_source } profiles { uuid id PK "linked to auth.users" string username int rank_points } challenges ||--o{ user_interactions : "has" profiles ||--o{ user_interactions : "interacts" challenges }o--|| profiles : "created by"

The challenges.votes column is maintained by a PostgreSQL trigger that recomputes SUM(vote_type) from user_interactions on INSERT / UPDATE / DELETE. Voting uses PostgREST upsert with on_conflict=user_id,challenge_id and resolution=merge-duplicates.

PrimRec Language Pipeline

flowchart LR SRC["Source Code"] --> LEX["Lexer
hand-written tokenizer"] LEX --> PAR["Parser
recursive-descent"] PAR --> AST["Program AST
diagnostics + ranges"] AST --> VAL["Validator
scope, arity, cycles"] VAL --> NORM["Normalizer
to CoreExpression"] NORM --> INT["Interpreter
compile to JS closures"] INT --> RESULT["Evaluation Result"] AST --> MONACO["Monaco Markers
diagnostics in editor"] AST --> DISCOVER["Function Discovery
names, arities, params"] DISCOVER --> SIDEBAR["FunctionsPanel"]

The interpreter compiles expressions to native JavaScript closures. Three idiom-recognition patterns detect predecessor, constant-after-first-step, and linear recurrence patterns for O(1) closed-form evaluation instead of recursive computation.

Key Design Decisions

Optimistic Updates

Vote changes are applied instantly in the UI. On API failure the snapshot is restored. Binary-search insertion maintains sort order in O(log n) instead of O(n log n).

Pagination Everywhere

Challenge lists and leaderboards use limit/offset pagination (50 per page). Search is debounced at 300ms. GetVoteMapAsync capped at 100 IDs.

Immutable Color System

All 12 themes generated from a single base hue via programmatic lighten/darken. OLED-black overrides swap background colors. No per-theme CSS duplication.

DB-Enforced Vote Integrity

A PostgreSQL trigger recomputes votes from the user_interactions table. The API only manages interaction rows — vote counts are always consistent.
